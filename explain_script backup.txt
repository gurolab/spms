SMS Stakeholder Presentation Script
For Cotabato State University Stakeholder Presentation
Prepared on: March 8, 2026

====================================================================
1) Opening Script (Use This First)
====================================================================

Good day, everyone. Thank you for giving us time to present my capstone system,
SMS or Supply Management System in the context of State University.

This system digitizes the university flow of:
1. Requesting supplies or property
2. Approving and issuing items
3. Tracking stock and accountability
4. Producing compliance reports
5. Recording audit trails

Our design follows role-based access, so each office sees only what is relevant
to their function, while still keeping a complete institutional record.


====================================================================
2) Simple Non-IT Illustration
====================================================================

Think of SMS as one shared official logbook with six counters:

- Employee Counter: places requests
- Supply Counter: receives and issues supplies
- Inventory Counter: monitors stock levels and reorder risks
- Property Counter: tracks non-consumable assets and transfers
- Auditor Counter: reviews compliance reports and logs
- Admin Counter: manages users, settings, and full oversight

Illustration of data flow:

Employee Request (RIS)
        |
        v
Supply Review + Issuance (RSMI)
        |
        +--> Stock Balance + Ledger Update
        |
        v
If item is property/non-consumable:
ICS/PAR + Property Card + Transfer Tracking
        |
        v
Audit Logs + Compliance Reports (RPCI/RPCPPE/IIRUP)

4) Script Per Role
====================================================================

--------------------------------------------------------------------
A) EMPLOYEE ROLE SCRIPT
--------------------------------------------------------------------

Screen path:
- Dashboard: employee/dashboard.php
- Request page: employee/requisition.php
- Request details: employee/request-details.php
- Status page: employee/acknowledgment.php

What to say:

1. "As an employee, I can create my own request without manual paper routing."
2. "In Request Supplies and Property, I click Create New Request, enter date,
   fund cluster, purpose, and remarks."
3. "After creating the header, I open the request and add line items."
4. "While status is Requested, I can still edit quantity or remove a line."
5. "Once processing starts, the request becomes locked for integrity."
6. "In View Status, I can monitor RIS progress and also see active ICS/PAR
   records assigned to me."

Business value line:
- "Employees gain transparency. They no longer need to guess if their request
  is pending, partially issued, or completed."


--------------------------------------------------------------------
B) SUPPLY OFFICER ROLE SCRIPT
--------------------------------------------------------------------

Screen path:
- Dashboard: supplyofficer/index.php
- Receive: supplyofficer/receive.php
- Manage RIS: supplyofficer/ris.php
- Issue Supplies: supplyofficer/issue_supplies.php
- Inventory reports: supplyofficer/inventory_reports.php

What to say:

1. "As Supply Officer, my dashboard shows receipts logged, quantity received,
   pending RIS, and open issuances."
2. "In Receive Supplies, we log incoming deliveries by receipt number, supplier,
   date, and receiving details."
3. "When we add received items, stock quantities are updated automatically,
   and movement is recorded in stock/ledger history."
4. "In Manage RIS, we monitor request status from Requested to Completed."
5. "In Issue Supplies, we create an issuance (RSMI), then add line items based
   on RIS remaining quantity and available stock."
6. "The system prevents over-issuance and auto-updates item issuance progress
   and RIS status."

Business value line:
- "This reduces manual errors in issuing and gives traceable proof for every
  release transaction."

====================================================================
5) Evaluation Summary (Stakeholder-Friendly)
====================================================================

Current strengths observed:
1. Clear role-based access by function (Employee, Supply, Inventory, Property,
   Auditor, Admin).
2. End-to-end supply process is integrated:
   receiving and issuing update stock balances and ledger history.
3. Employee self-service request and status tracking is operational.
4. Property accountability modules (ICS, PAR, property cards, transfers)
   are operational.
5. Authentication includes rate-limit protection and audit logging.
6. Audit log viewer includes scoped access, metadata view, and change trail.

Current limitations to disclose transparently:
1. Auditor dashboard analytics page itself is still marked as under development,
   while report pages are accessible.
2. Audit logging is strongest in authentication/profile/user/supplier/employee
   request actions; some other modules can still be expanded for deeper
   action-by-action logging coverage.
3. CSRF protection for most forms relies on JavaScript token injection,
   so browser script execution must remain enabled in production.

6) Suggested Stakeholder Q&A Script
====================================================================

Q: "Can this reduce delays in request processing?"
A: "Yes. Requests, issuance progress, and accountability status are visible
in one system, reducing follow-up delays and duplicate paper coordination."

Q: "How do you ensure accountability?"
A: "Every role has controlled access, and key actions are recorded in the
activity log with user identity, timestamp, and metadata."

Q: "How do we know stock is accurate?"
A: "Stock updates are event-driven from receiving and issuance, then reflected
in stock cards, reconciliation watchlists, and ledger entries."

Q: "Can this support compliance reporting?"
A: "Yes. RPCI, RPCPPE, and IIRUP modules are included with report headers,
line items, and printable outputs."

Q: "What is next after this presentation?"
A: "Next steps are pilot rollout by office, expanded audit coverage for all
modules, and enhancement of auditor analytics dashboards."
